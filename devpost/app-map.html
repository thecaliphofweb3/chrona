A compact guide to the finished proof of concept

Chrona

Chrona helps someone begin the day with encouragement, a time plan, a meal plan, and a simple outfit preview. The main React screen chooses which area to show; small components handle each area; the browser saves the plan locally.

One action, from typing to result

Reference route: follow a schedule entry

  1. 1. src/components/SchedulePlanner.jsx — addPlan
    This is the entry point. It checks that a description and time exist, creates the new plan object, and sends the updated list upward.
  2. 2. src/App.jsx — updateSchedule
    This is the shared plan holder. It replaces only the schedule part of the day plan, while keeping meals and body shape unchanged.
  3. 3. src/lib/storage.js — saveDayPlan and loadDayPlan
    These functions write the plan to this browser and restore it when the app opens again. Nothing is sent to a server.

To change this, start here

Change the schedule form words or fields: edit the labels and inputs in src/components/SchedulePlanner.jsx.
Change how long the browser checks for a due plan: find setInterval(checkForDuePlans, 10_000) in src/App.jsx.
Change the welcome or planner look: edit the matching screen rules in src/styles.css. The supplied image files live in public/assets/.

A practice to reuse

For this project, “a plan stays after refresh” was a visible promise. The code route above lets you connect that promise to the browser-storage functions, and the production build (npm run build) confirmed the finished site compiles. On another project, choose one visible promise first, then trace its input, the place that holds the data, and the result the person sees before changing it.

Run it again

In the project folder, run npm install once, then npm run dev and open the address it prints. Run npm run build to create the deployable version in dist.
